# Монтаж по референсу

Вход: **видео спикера** (ИИ-аватар или живая запись) + **ролик-референс** (донор), который нравится клиенту.
Донор задаёт **скелет**: темп, порядок и типы сцен, удачные экраны. Живые демо продукта из донора можно взять
как b-roll. Остальное собираем из библиотеки сцен в стиле студии. Тайминг ведёт **наша озвучка**.

Общие правила (хук, ритм, субтитры, звук, проверка) — в `docs/DIRECTOR.md`. Здесь только отличия.

> Референс **стиля** (как должны выглядеть все ролики) разбирается один раз в `/setup-studio` и живёт в
> `studio/references/`. Референс **ролика** (как смонтировать именно этот) — здесь, в `videos/<slug>/ref/`.

## Шаги

1. **Речь:** живая запись → `tools/cleanup.py` (план → проверка → `--apply`) → `transcribe.py source/clean.mp4`;
   ИИ-аватар → сразу `transcribe.py`.
2. **Посмотри донора:** ссылка или файл → `python3 tools/watch.py <ссылка|файл>` (скачает по ссылке в
   `videos/_watch/<имя>/video.mp4`). **Разбор донора:** `python3 tools/ref_analyze.py <video.mp4> videos/<slug>` → `ref/analysis.md` (шоты · время · речь
   донора), `ref/sheet.jpg` (контакт-лист), `ref/frames/` (крупные кадры). Посмотри картинки.
3. **Заполни в `analysis.md` колонку «решение»** для каждого шота:
   - `b-roll` — живая демонстрация продукта (запись экрана, анимация интерфейса). Кроп:
     `python3 tools/clip.py donor.mp4 media/x.mp4 --ss S --t T --crop 0,0,720,570`; на весь экран — `--size 1080x1920 --fit blur`.
     Шоты с лицом донора, его субтитрами и водяными знаками — **никогда**.
   - `сцена <kind>` — экран, который лучше перерисовать нашей сценой (цена → `number`, список → `list`,
     сравнение → `compare`, интеграции → `hub`…). Данные свои и проверенные.
   - `пропустить` — к нашему сценарию не относится.
   - `нет в библиотеке` — приём, которого у нас нет (особый переход, эффект). Скажи клиенту простыми словами и
     предложи: похожая наша сцена / новая через `html` (выйдет попроще) / пропустить.
4. **Сопоставь с нашей озвучкой:** каждой фразе — шот донора с тем же смыслом или своя вставка.
   Порядок и плотность смен берём у донора; длительность — по нашим словам (`from_w/to_w`).
5. **Начало ролика** — по `DIRECTOR.md §Б1`: у донора заголовок в первые секунды — делаем свой, не копию;
   у донора сразу человек — и у нас так.
6. **Движение и вид карточек** донора — это стиль клиента: сверь с `motion.feel` и `surface.kind` студии; отличается —
   спроси клиента, брать ли для этого ролика (`"motion"`, `"surface"` в shotlist.json) или для всех (`/style-lab`).
7. Дальше общий конвейер: `shotlist.json` → `music.py` → `build.py` → `check` → снапшоты → рендер.

## Правила режима
- Субтитры, лицо и голос донора не переносим. Подписи и плашки — наши.
- Вставка из донора ≤ 6 с подряд; между ними — наши сцены или удар на лицо.
- Донор обычно 720p: для полного экрана и хука кадрируй плотно и проверяй резкость на снапшоте.
- Чужой контент — только как ориентир и короткие демо продукта. Авторские права на донора у его автора.
