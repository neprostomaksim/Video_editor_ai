# Правила режиссёра: сценарий → раскадровка

Режиссёр — это ИИ-агент в сессии. Вход: `transcript.txt` (слова с таймкодами и индексами), профиль студии
(`studio/profile.md` — кто смотрит, тон, запреты; `studio/studio.json` — стиль и темп) и, если есть, референс.
Выход — `shotlist.json`. Движок сам собирает ролик (`engine/build.py`). **Графику руками в HTML не пишем**: только
JSON с выбором сцен и данными. Исключение — сцена `html` для уникальной метафоры.

Параметры сцен: `python3 engine/catalog.py` (или `catalog.py list`).

**Перед раскадровкой прочитай `studio/profile.md`**: тема, источник видео, стиль, CTA и прошлые правки клиента —
их не повторяем.

---

## 0. Темп студии (`studio.json → montage.pace`)

| pace | Что делаем |
|---|---|
| `minimal` | Спикер почти всё время в полном кадре. Субтитры, наезды (`punches`), 2–4 титула (`title`), хук и CTA. Графика — только когда без неё непонятно (цифра, список). Для экспертов, психологов, лайфстайла |
| `standard` | Скелет из §1: хук, split-сцены каждые 2–4 с, 2–3 полноэкранные вставки, удары на лицо |
| `dynamic` | Смена каждые 1–2 с, больше полноэкранной графики и b-roll, удары на каждом тезисе. Для обзоров, новостей, техно |

`montage.split: false` — не использовать раскладку split (графика только full/overlay).
`montage.full_graphics: false` — без полноэкранной графики. `montage.punches: false` — без наездов.

## 1. Скелет ролика

| Отрезок | Что на экране |
|---|---|
| Хук, первые 2–4 с | **всегда `hook`** (§1а): цепляющий заголовок 2–6 слов + движение с первого кадра |
| Основная часть | **split**: графика сверху, спикер снизу. Смена сцены каждые **1.5–4 с**, по смыслу фразы |
| Ключевой тезис / эмоция / «секрет» | **полный кадр спикера** на 1.5–3 с + `punches` (наезд на лицо) |
| Короткие «вау»-вставки | `layout: "full"`: графика на весь экран, спикер скрыт (≤ 3–4 с, 2–3 раза за ролик) |
| Финал | **полный кадр спикера** + `cta` (кодовое слово из последней фразы) |

Субтитры движок ставит сам (стиль — `studio.json → captions`): в split — на стыке графики и спикера, на полном
кадре и полноэкранной графике — в нижней трети. Руками не двигай без просьбы клиента.

Паузы между сценами до 0.3 с не оставляй: `to_w` одной = слово перед `from_w` следующей.
Промежуток без сцены = полный кадр спикера, и это тоже монтажный приём, а не дыра.

## 1а. Хук: первые 3 секунды решают, будут ли смотреть

Пропуск (skip rate) в Instagram — доля зрителей, листающих дальше в первые 3 секунды.
Ориентиры: < 30 % хорошо, 30–40 % слабо, > 40 % хук не работает.

1. **Хук стоит с кадра 0.00**, ничего не «появляется». Первый кадр = обложка в ленте (движок сам ставит hook в 0).
2. **Результат или выгода, а не логотип.** Логотип неизвестного продукта крупно = сигнал рекламы → пропуск.
3. **Понятно без звука за 1 секунду:** 2–6 слов, одна мысль, конкретика (цифра, цена, срок, «как у …»).
4. **Движение с первого кадра.** Медиа хука — видео (демо, запись экрана, b-roll) или анимированный HTML-макет,
   записанный в mp4: `node tools/html_record.mjs mock.html media/hook.mp4 1080 1010 --dur 4`. Статичный PNG — крайний случай.
5. **Голос = картинка:** что говорит спикер, то и видно. Слабая первая фраза (приветствие, разгон) —
   компенсируем визуалом и советуем клиенту переписать первую фразу.
6. **Текст хука не лежит на лице:** в стилях face/comment движок сам опускает спикера (`drop`) и заполняет верх
   размытой копией кадра. Голова выше/ниже обычного → поправь `source.face_top` в studio.json.
7. Верх ~200 px и низ ~350 px кадра закрыты интерфейсом Instagram/TikTok: важное туда не ставим.

**Хук — от боли зрителя.** Заголовок = проблема/возражение зрителя (бери из сценария) или результат в его
деньгах/времени, а не название инструмента. Стиль по умолчанию — `montage.hook_style` студии.

| Ситуация | Стиль `hook` |
|---|---|
| Ответ на возражение/комментарий («это сложно», «это дорого», «не работает») | `style: "comment"` + `comment: {"name", "text", "likes"}` |
| Есть демо/результат/красивый кадр | `style: "split"` — демо сверху с заголовком, спикер снизу |
| «Вау»-кадр сильнее лица | `style: "result"` — демо на весь экран + заголовок |
| Нет картинки, есть сильный факт (цена, цифра, «замена X») | `style: "face"` — полный кадр спикера, над головой заголовок + `price`/`proof` |
| Связка «X теперь работает с Y» | `style: "face"` + `apps: {"from": "...", "to": [...], "more": "+1000"}` |

Формулы заголовка: «[результат] *за 0 ₽*» · «[действие] *за N секунд*» · «[что было] → *[что стало]*» ·
«ошибка, из-за которой *[боль]*» · «[N] способа *[выгода]*». Цены и цифры — только проверенные.
Сомневаешься — собери 2–3 варианта (`build.py --shot shot_hookA.json --pub public_hookA --duration 6.5`) и покажи клиенту.

## 1б. Ритм

**Что-то меняется в кадре каждые 1.5–2.5 с** (сцена, раскладка, наезд, новый элемент). Движок сам делает
jump-cut наезды 1.0 ↔ 1.1 на начале фраз и на каждой склейке чистки живой записи (`cuts.json`).
- **Читаемость на телефоне:** текст в графике ≥ 34 px, в кадре ≤ ~15 слов. «Простыни» (страницы сайтов, длинные
  интерфейсы) — не дольше 2 с и с наездом на нужное место.
- **Полноэкранная графика** (`layout: "full"`): 2–4 раза за ролик, 1.5–3.5 с. 16:9-видео на весь экран:
  `python3 tools/clip.py src.mp4 media/x.mp4 --ss 3 --t 3 --size 1080x1920 --fit blur`.
- **Удары на лицо**: 0.4–1 с на словах-маркерах («Первое», «Но», «Секрет») + `punches`.

## 2. Какую сцену выбрать под фразу

| Во фразе… | Сцена |
|---|---|
| конкретное число: цена, срок, процент, «в 5 раз» | `number` |
| перечисление: «3 ошибки», «во-первых… во-вторых…», шаги | `list` (пункт появляется на своём слове через `w`) |
| «X против Y», «было/стало», «дорого/дёшево» | `compare` |
| короткий ударный тезис без данных | `text` |
| тезис на полном кадре спикера | `title` (overlay) |
| называется продукт/сервис/приложение (первое упоминание) | `product` |
| перечисление брендов/приложений подряд | `logos` (каждому `w` — слово, где он звучит) |
| «работает с A, B, C», интеграции | `hub` |
| новость, пост, отзыв, скрин сайта | `image` (`node tools/web_capture.mjs <url> captures/x.png`) |
| работа продукта, процесс, «вот как это выглядит» | `video` (b-roll: запись экрана, съёмка, промо) |
| «открываешь ChatGPT/Claude и пишешь…» | `chat` |
| «зайди в настройки → включи X» | `settings` |
| репозиторий на GitHub | `github` (`node tools/github_capture.mjs owner/name videos/<slug>`) |
| команда в терминале | `terminal` |
| файл, код, конфиг | `code` |
| быстрое упоминание сервиса мимоходом | `sting` (overlay) |
| уникальная метафора, которой нет в библиотеке | `html` |
| начало ролика | `hook` |

Для не-технических тем (лайфстайл, эксперты, бизнес) основа — `hook`, `title`, `text`, `list`, `number`,
`compare`, `image`, `video` и полный кадр спикера с ударами. Технические сцены (`github`, `terminal`, `code`,
`chat`, `settings`) — только когда о них реально говорят.

## 3. Жёсткие правила

1. **Факты не выдумываем.** Числа, названия, цены, цитаты — только из озвучки, проверенных источников
   (сайт, API) или от клиента. Нет значения — спроси или не показывай.
2. **Звёзды GitHub показываем, если их ≥ 2000.** Меньше — только название репо.
3. **Логотипы только из библиотеки:** `python3 tools/logos.py find "имя"` → нет: `fetch <slug>` (lobehub) →
   нет: `add <slug> <файл|url> "Имя" "как звучит в речи"`. Буквенная плитка-заглушка в финале недопустима.
4. **Интерфейсы сервисов — в их родных цветах.** Стиль студии (акцент, плашки, шрифты) — поверх:
   субтитры, акценты `*слово*`, плашки, CTA.
5. **Одна мысль на сцену.** ≤ 5 пунктов в `list`, ≤ 6 спутников в `hub`, ≤ 8 логотипов в `logos`.
6. **Синхрон со словом.** Элемент появляется на слове, где он звучит (`w`), а не равномерно.
7. **ASR проверяй глазами.** Прочитай `transcript.txt`, исправь названия в `words.json`; повторяющуюся ошибку
   добавь в `studio/glossary.json`. Слова, «сжатые» в доли секунды, — ошибка тайминга: поправь `start/end` по соседям.
8. **Кодовое слово CTA** — ровно из финальной фразы («напиши ГАЙД…» → `"word": "ГАЙД"`).
9. **Правки клиента из профиля** — закон: однажды попросил — больше не повторяем.

## 4. Формат shotlist.json

```json
{
  "fps": 25,
  "cta": {"from_w": 118, "word": "ГАЙД"},
  "punches": [{"w": 40, "scale": 1.15, "dur": 2}],
  "scenes": [
    {"kind": "hook", "style": "face", "from_w": 0, "to_w": 6, "lines": ["3 ошибки", "*в первом ролике*"]},
    {"kind": "list", "from_w": 7, "to_w": 30, "heading": "Ошибки", "items": [{"text": "Нет хука", "icon": "cross", "w": 12}]},
    {"kind": "number", "layout": "full", "from_w": 31, "to_w": 38, "value": 73, "suffix": "%", "label": "пролистывают"}
  ]
}
```

- Время сцены: `from_w`/`to_w` (индексы слов из `transcript.txt`) **или** `start`/`end` в секундах.
- Время элемента внутри сцены: `"w": <индекс слова>` или `"t": <сек>`.
- `layout`: `split` (по умолч.) | `full` | `overlay`; `bg`: `light` (по умолч.) | `dark`.
- `*слово*` в текстах = маркер акцентного цвета.
- Переопределить стиль для одного ролика: `"theme": {"accent": "#..."}`, `"captions": {...}`, `"avatar": {...}`
  (как `source` в studio.json), `"cta_style": {...}`, `"sfx": {"enabled": false}`.

## 5. Проверка перед рендером

1. `python3 engine/build.py videos/<slug>`: читай предупреждения (⚠), исправляй.
2. `cd videos/<slug> && npx hyperframes check public`: **0 errors**.
3. `npx hyperframes snapshot public --at t1,t2,… --describe false` (кадр 0 + середина каждой сцены) →
   **посмотри `public/snapshots/contact-sheet.jpg` сам**: текст не вылезает, логотипы правильные, ничего не
   перекрывает лицо, субтитры читаются.
4. Раскадровку до рендера коротко покажи клиенту таблицей «время — сцена — что на экране».

## 6. Звук

- **Голос** `transcribe.py` выравнивает до −15 LUFS.
- **Эффекты** (`sound.sfx`): свуш на смене раскладки, pop на числах и CTA, клики в списках, печать в чате.
  Громкость откалибрована: на 5–6 дБ тише голоса. Файлы — `assets/sfx` (Pixabay, коммерческое использование разрешено).
- **Музыка** (`sound.music`): `python3 tools/music.py videos/<slug>` — темп по речи и монтажу, трек из
  `studio/music/` (свои с лицензией) или каталога HeyGen. В сборке музыка уступает голосу в его частотах (carve).
